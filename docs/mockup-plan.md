# モックアップ実装計画書

[要件定義書](./requirements.md) の詳細ドキュメント。本実装（React + Spring Boot）の前に、画面と動きを目で確かめるために作ったモックアップの内容と、確かめた結果をまとめる。

## 目的と作り方

- [機能要件](./features.md)・[画面仕様・画面遷移・ユースケース](./screens.md)・[API 設計](./api.md) を決めた段階で、画面の並び・入力の流れ・計算の結果（自己ベスト・集計・目標の達成率など）が、文書の決まりどおりで使いやすいかを確かめる
- 前回の SNS アプリと同じく、**バックエンド・ビルドツール・外部のライブラリを使わない、静的な HTML・CSS・JavaScript** で作る。データはブラウザのメモリだけに持ち、再読み込みで初期データに戻る
- 置き場所は `mockup/`（リポジトリ直下。本実装の `frontend/` とは別）

## 開き方

`mockup/index.html` をブラウザで直接開く（または `cd mockup && python3 -m http.server 8000` で `http://localhost:8000`）。

- ログイン画面の「デモ用アカウント」を押すと入力される（パスワードはすべて `password123`）
- 画面の一番上の帯に、モックだけの操作を置いた
  - 「📬 モックのメール」：本番ではメールで届く、確認用・再設定用のリンクを開く（新規登録・パスワードのリセット・メールアドレスの変更を試すため）
  - 「👟 仲間が投稿する」：フォロー中の仲間の投稿を1件作る（ホームの「↑ N件の新しい投稿」を試すため）

## 画面の切り替え

URL のハッシュ（`#/...`）で画面を切り替える。URL は画面仕様の React のルートと同じ形にした（例：`#/workouts/12`・`#/records?week=2026-11-09`）。ページを読み込み直さないので、ログアウトして別のユーザーでログインし直しても、データは残る（第三者として操作した結果を確かめられる）。

- 未ログインでログインが必要な画面を開くと `#/login?next=…` へ移動し、ログインしたらもとの画面に戻る
- 画面の一覧にない URL は `#/`（未ログインなら `#/login`）へ移動する

## 本実装と違うところ（モックだけの割り切り）

| 項目 | モック | 本実装 |
|---|---|---|
| データ | メモリだけ。再読み込みで初期データに戻る | PostgreSQL |
| グラフ | SVG を自前で描く（値に乗せると数値、「表で見る」で表） | Recharts |
| 新しい投稿・未読数の確認 | 10秒ごと（確かめやすくするため） | 60秒ごと |
| メール | 画面の「📬 モックのメール」に入る | SES（手元は Mailpit） |
| 画像 | 選んだ画像をブラウザで縮小し、data URL で持つ | S3 と署名付き URL |
| 保存の確定後の処理 | 保存の直後に同じスレッドで判定する | 確定後に別のスレッド |
| 通信の失敗・読み込み中の表示 | 通信がないので出ない | 画面仕様のとおり |
| ログイン状態の保持（UC-07） | 再読み込みで消える | リフレッシュトークン |

## 確かめたこと

Chrome（DevTools）で、パソコン幅とスマートフォン幅の両方で確かめた。

- **全画面を開く**：46の URL（23画面と、そのタブ・期間・状態の違い）を順に開き、JavaScript のエラーが0件であること
- **記録の作成**：種目の選択（半角カナ「ﾍﾞﾝﾁ」でもベンチプレスが見つかる）→ 刻みの違反（60.1kg）で赤字とボタンの無効 → 直前の値でセットを追加 → 一時保存 → 投稿 → 詳細に移り「🏆 ベンチプレスの自己ベストを更新しました！」、一時保存が消える
- **目標**：ベンチプレス 100kg の記録で重量の目標が達成済みになり、通知が1件増える。期限切れのデッドリフトの目標は達成にならない
- **単位**：lb・マイルに切り替えると、投稿カード・ランニングの集計・ペースが切り替わる
- **鍵アカウント**：佐藤（リクエスト2件）が鍵アカウントをやめると、2件とも承認され、`follow_accepted` が届き、`follow_request` の通知が消える
- **認証**：新規登録の入力チェック → 登録 → モックのメールから確認 → 確認済み。パスワードのリセット → 再設定 → 同じリンクは2回使えない → 古いパスワードでは入れず、新しいパスワードで入れる
- **データと計算**：Node.js で `data.js` だけを動かし、閲覧の制御（リクエスト中の人に鍵アカウントの投稿が見えない）、ハッシュタグの取り出し（31文字以上・全角の `＃ＡＢＣ`）、消費カロリー、推定 1RM を確かめた

## モックアップで確かめられなかったこと

モックは通信・非同期の処理・保存先を持たないため、次の点は本実装の各段階のテストで確かめる。

| 項目 | モックでの扱い | 本実装で確かめる場所 |
|---|---|---|
| 通信の失敗・読み込み中の表示 | 出ない | 画面のテスト（読み込み中・空・エラーの状態。[テスト計画書 3章](./test-plan.md#3-テストの層)） |
| 画像のアップロード | ブラウザで縮小して data URL で持つ | 結合テスト（S3 への保存と後片付け）と E2E（署名付き URL での表示） |
| 目標の達成の通知 | 保存の直後にすぐ届く | 本実装では保存の確定後に別のスレッドで作り、画面には未読数の次の確認（60秒ごと）で出る。結合テストは Awaitility、E2E は待ち方を決めて確かめる（[テスト計画書 8章](./test-plan.md#8-進め方)） |
| ログイン状態の保持（UC-07） | 再読み込みで消える | E2E（Cookie でのログインの維持） |

## 本実装が始まってからの扱い

- モックアップは**本実装の段階 0 からは直さない参考資料**とする。画面や決まりを変えるときは、設計書（機能要件・画面仕様・API 設計）を直し、モックアップは追いかけない
- **テストの期待値はモックアップから写さない**。`mockup/js/data.js` にも自己ベスト・集計・達成率・閲覧の制御の計算を書いているが、ここから期待値を写すと、モックアップの間違いまで本実装のテストに写ってしまう。期待値は、設計書とテスト計画書から手で決める（テスト駆動の進め方。[CLAUDE.md](../CLAUDE.md)）
- 本実装の ESLint・Prettier・CI の対象から `mockup/` を外す（段階 0 で設定する。[テスト計画書 8章](./test-plan.md#8-進め方)）
